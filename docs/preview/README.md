# 静态 UI 预览（设计前置）

**规则（2026-10-04 用户裁决）**：所有涉及界面/版式的任务，**先在**这里出静态网页预览、
与用户确认形态，**才**进 `src/` 实现。理由：先落地再改的返工代价远高于先把形态对齐
（0.9.134–0.9.138 评论观感连返四轮即教训）。

**文档站化（2026-11-23 用户裁决）**：全部确认稿已重构为统一文档站形态——共享 chrome
（`_docs.css` + `_docs.js`：左侧分组导航、顶栏面包屑、页头徽章体例），demo 区仍单文件
保真。配套项目宣传首页在仓库根 [`index.html`](../../index.html)。

## 怎么用

1. 复制 [`_template.html`](_template.html) → `docs/preview/<特性名>.html`（**单文件**：无构建、
   无依赖，双击即可打开；也可 `npx serve .` 后访问 `/docs/preview/<特性名>.html`）。
2. 用**项目真实口径**画：暗色皮肤变量取自 `src/styles.js`（`--acsv-accent:#fd4c5d`、底 `#000`、
   字 `#fff`、圆角/字号/间距照既有类名量值），文案用真实中文而非 Lorem。
3. **关键状态全摆出来**：默认 / 悬停 / 选中 / 空态 / 错误态 / 窄宽（540px 另开一段 `@media` 或用
   `state-*` 类模拟）。一屏看不全就纵向排几段，每段上方写小字标注状态名。
4. 按 **1600×900 桌面视口**自检一遍（项目主视口），再按 540 宽扫一眼窄态。
5. 用户确认后：预览稿**留在仓库**（设计存档）；实现按预览逐项对齐，后续改版**先改预览**再改代码。

## 页间切换（2026-11-23：左栏常驻，不整页刷新）

- **http(s)**：`_docs.js` 走 fetch 无刷新换页（内容区原地替换、样式随之切换、滚动按页记忆：回访恢复 / 首访置顶 / 后退恢复）。
- **file://（双击打开）**：fetch 不可用，改用**常驻壳**——左栏/顶栏不动，内容装进内嵌 frame，
  切页只换 frame（`#/页名.html` 记入地址，刷新可还原）；内嵌页 `postMessage` 回同步高亮与面包屑。
- 共享件引用带版本参数（`_docs.css?v=…` / `_docs.js?v=…`），改共享件时**同步升版本号**，防浏览器旧缓存。

## 结构契约（chrome 归共享层，demo 归本页）

- chrome（侧栏/顶栏/页头/段落徽章/取值 pill/文档表/档案折叠/本页目录右栏/段内栅格）=
  `_docs.css` + `_docs.js`，各页**只引用不重写**；`_template.html` 是体例正主。
- demo 区（组件样例与样式）= 本页 `<style>`，量值照抄 `src/` 真值，不另立一套。
- **新页登记**：`_docs.js` 的 NAV 注册表是导航单源，新增确认稿只改注册表，别在页内手写导航。

## 图标与资产（2026-11-23 用户裁决：预览必须与落地同件）

- **脚本 UI 图标一律取落地真载体**：iconfont 字形（码点来源 `src/imicons.js` GLYPHS）/
  `src/styles.js` 的 ICONS 内联 SVG 原件 / SITE_ICONS（小视频站 PNG）/ VIDEO_ICONS、ICON_SVGS
  （站方 SVG，作 mask）/ `src/pubfab.js` ICON_PEN_D。禁手绘近似与 emoji 替身。
- **站方资产已入库** `docs/preview/assets/`：字体 `acfun-frontend-next.woff/.ttf` +
  `site-heart/comment/share.png` + `video-like/favorite/banana/banana-on.svg` +
  `icon-view-player/message.svg`。各页 `<head>` 的 `@font-face` 与 mask/img 一律引用本地
  `assets/`（file:// 双击、离线均可显示）。**assets 只作预览保真用，实现侧仍从 CDN 取，
  勿在 `src/` 引用**——它是稿的资产副本，不是第二份实现单源。
- 豁免（保留原样）：装饰性元素（窗口圆点/占位渐变/头像占位/示意标注）；落地本身就用文本的
  字符（`⋮` / `✕` / `×` / `＋` / `↩` / `弹` 等按钮文字）——它们就是实现载体，勿"图标化"。

## 版面三件套（2026-11-23 用户裁决）

1. **决策档案折叠**：决策沿革段（现状矩阵/提案矩阵/token 表/裁决登记/落点表/修法推导）
   收进页尾 `<details class="doc-arch">`（summary＝组名+hint+节数 pill，样式在 chrome）；**状态成品展示
   永不折**（含「改前/改后」对照列但主体是实物 demo 的段也算成品）。成品段提前为主体、idx 从 01
   顺编；有明确落地裁决的稿在 doc-meta 后补一句「本稿结论」。被折段内容/锚点 id 原样、去 idx。
2. **横屏利用**：内容栏 1360 上限；≥1700px 视口出右缘「本页目录」栏（`_docs.js` 自动生成节锚点，
   档案组自动二级收纳）；同段 ≥2 个同形窄 demo（≤~420px）用 `.doc-grid` 并排——**宽表/矩阵不进
   栅格、跨段不拆段并列**。
3. 口径拿不准时倾向不折/不栅格，并在改版记录里注明。

## 边界

- 预览只管"长什么样"（版式/尺寸/层级/文案）；数据、交互、边界条件归代码。
- 预览稿**不参与**构建与测试（`src/` 是唯一实现），别把预览里的样式直接拷进 `styles.js` 当
  第二份来源——落地时按模块既有结构改写。
- **命名与改版（2026-11-23 用户裁决修订）**：一稿一文件 `<特性名>.html`；大改版**原地重构**
  （历史形态靠 git 追溯，目录不留双份）。此前「大改版加 `-v2`、别覆盖历史稿」的规矩同批废止——
  对比走 `git log/show`，不再靠并存文件。
- **追补稿**：规矩入册前已落地的 UI，按**已出货形态**回画存档时，页首标「追补稿（回画 · 非事前确认）」
  并注明对应版本（先例：`follow-groups.html`/`fav-folders.html`，0.9.150）——别假装事前确认；此后
  该特性的改版仍先改稿再改码。
