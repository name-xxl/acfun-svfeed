# 静态 UI 预览（设计前置）

**规则（2026-10-04 用户裁决）**：所有涉及界面/版式的任务，**先在**这里出静态网页预览、
与用户确认形态，**才**进 `src/` 实现。理由：先落地再改的返工代价远高于先把形态对齐
（0.9.134–0.9.138 评论观感连返四轮即教训）。

## 怎么用

1. 复制 [`_template.html`](_template.html) → `docs/preview/<特性名>.html`（**单文件**：无构建、
   无依赖，双击即可打开；也可 `npx serve .` 后访问 `/docs/preview/<特性名>.html`）。
2. 用**项目真实口径**画：暗色皮肤变量取自 `src/styles.js`（`--acsv-accent:#fd4c5d`、底 `#000`、
   字 `#fff`、圆角/字号/间距照既有类名量值），文案用真实中文而非 Lorem。
3. **关键状态全摆出来**：默认 / 悬停 / 选中 / 空态 / 错误态 / 窄宽（540px 另开一段 `@media` 或用
   `state-*` 类模拟）。一屏看不全就纵向排几段，每段上方写小字标注状态名。
4. 按 **1600×900 桌面视口**自检一遍（项目主视口），再按 540 宽扫一眼窄态。
5. 用户确认后：预览稿**留在仓库**（设计存档）；实现按预览逐项对齐，后续改版**先改预览**再改代码。

## 边界

- 预览只管"长什么样"（版式/尺寸/层级/文案）；数据、交互、边界条件归代码。
- 预览稿**不参与**构建与测试（`src/` 是唯一实现），别把预览里的样式直接拷进 `styles.js` 当
  第二份来源——落地时按模块既有结构改写。
- 命名：一稿一文件 `<特性名>.html`；同一特性的大改版加 `-v2`，别覆盖历史稿（对比要看得到）。
