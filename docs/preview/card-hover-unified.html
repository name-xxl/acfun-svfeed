#裁决点建议值取舍与代价
① 分区卡撤不撤 accent 描边本批核心 撤——.acsv-jx-card:hover 的 border-color:var(--acsv-accent-dim) 整条删 与 0.9.314 撤行卡族红框同一理由：用户实看暗皮判「红框突兀」（cssraw 1647–1651 / moment-strip-actions.html v5 修订 ①）。 分区卡那圈是同一档 rgba(253,76,93,.55)，只是画在真边框上而非 overlay 环上。 撤后 hover 的可见反馈＝提底 .08 ＋ 封面 1.05 ＋ 标题红（三件，比现状那圈框信息量更大）。 基态 1px 透明边框保留（cssraw 286–287）——撤的只是 hover 的改色；连 border 声明一起删会带来 2px 布局差，不在本批。 代价：撤框需配一条防回潮负钉（分区卡 hover 不得再出现 border-color / outline / inset 阴影）。
② 封面卡标题是否仍变 accent本批核心 保留并推广——网格卡现状（cssraw 1281）不动，分区卡补同一条（作用在 .acsv-jx-ct） 三选一：A 保留并推广（本稿所画，四族里已有两处在册：网格卡 1281、榜单大卡 1124 ⇒ 它是既成语言，不是新发明）； B 只留网格卡、不给分区卡（则「我的页变红、分区页不变」的新落差会接替今天这一条）； C 全去掉（则封面卡 hover 只剩图元放大，暗底上「可点感」明显变弱，且要动两处已在册现状＝回归面更大）。 建议 A。注意分区卡标题是 2 行 clamp（cssraw 294–295），变红时是两行整体点亮；大卡标题 18px 单行也照同一档。
③ 提底档位是否统一到「基色 +.04」 分区卡 .04→.08 采（本稿所画）；榜单 .07 / 搜索 .03 本批不动，只统一「有提底」这件事 行卡族已定值是 .06→.10（+.04，cssraw 1658–1660）；照该档换算，分区卡该是 .04→.08（现状 .07，差 +.03 ⇒ 本批把它对齐）。 但榜单行与搜索行没有自己的基色底板（行体透明，hover 的 .07 / .03 是绝对值不是档位）⇒「基色 +.04」这条公式对它们无从套用： 套上去要先把「行的基色」定义出来，那是结构改动不是取值改动。 建议本批只做分区卡的 +.04 对齐，行式两族保留绝对值；若用户要「一眼全一致」，另一条路是把行式提底也定档（榜单 .07→.08、搜索 .03→.04 或 .08）， 但那是三个新值、且会改变榜单/搜索页的既有观感——本稿把它们照现状画，改动与否听裁决。
④ 按压幅度与方向 封面卡（网格 / 分区）＝:active{transform:scale(.985)}；行式卡（榜单行 / 搜索行）＝:active{transform:translateY(1px)} 两档都不是新值，是行卡族 0.9.314 已出货的两档（cssraw 1661–1664）。 方向纪律：缩放＝向内（0.985<1），位移＝向下（+1px），不许出现「上浮」这种反向。 为什么行式不给缩放：整行 scale 会牵动行内文本重排与行间分隔线抖动（0.9.314 同一判断）。 嫌轻可升档：封面卡 .985→.98（0.9.314 裁决点 2 已留这句话）；再大不建议——宫格/封面 1.05 与卡面 .985 的净差是 hover→press 的手感落差，缩到 .97 会把「按压」读成「卡塌了」。 本批新暴露的一处：分区卡大卡（.acsv-jx-big，跨 2×2）用同值 .985 时，其绝对位移明显大于普通卡（面积大一倍）——若嫌夸张，可另裁大卡档（如 .99），但那是新值、且给一族开出两档按压，本稿不推荐。
⑤ 本批范围要拍板 建议＝分区卡 + 网格卡（我的页 / 搜索视频网格 / 关注流视频卡）＋ 榜单行 ＋ 搜索行，四族全做 只做「分区 + 我的页」能灭掉用户这一句实报；但榜单/搜索仍是无按压的第三、第四套语言， 下一轮极可能再被点出来（0.9.314 那批当时也只行卡族，本轮即是它的续批——同一条缝第二次出血）。 四族全做的代价：改动面从 2 个视图扩到 4 个（cssraw 四段 + 一条 .acsv-jx-cv 结构补课，见 ⑨）， 且榜单页 / 搜索结果页需各自过一遍真机（本页改动是纯 CSS 选择器挂载，零 DOM 变更、零 JS 改动——见下方实现面）。 若用户只批「分区 + 我的页」，本稿的 ③ 段 C/D 两表仍留在仓库作后批设计存档，不删。
⑥ --acsv-accent-dim 的去留连带后果 本批删该变量（styles.js 194–195 那一段），不留零消费 token 撤掉分区卡描边（裁决 ①）后，这个「accent 半档」再无消费方——它现状由 .acsv-jx-card:hover 独用， 这件事 styles.js 190–191 的注释自己写着，而 0.9.314 撤行卡族红框时特意为它留了活口（「变量保留，现由 .acsv-jx-card:hover 独用」）。 也就是说：裁决 ① 一旦通过，那条留活口的理由就消失了。 留着＝零消费变量＋注释失真（比没注释更坏，见 README「病灶上溯结构」判定口径）；删＝顺带把 189–193 注释改写为「红框全族撤除，token 随批退役」。 本稿建议删；若将来要再加框，按 0.9.314 留档的教训走 overlay 环、届时再建同名 token（净减法可逆）。
⑦ 我的页管理键的显形过渡（.15s）要不要一并并到 .12s 不动（保持 cssraw 1449 的 opacity .15s） 「过渡统一 .12s ease」这条提案的作用面是卡面反馈（hover 提底 / 图元 / 标题 / 按压）； 管理键显形是操作入口的可见性，不是「这块可点」的语言。把它并档＝为统一而统一，且会让键出现得更急。 本稿不并，但登记出来请用户确认「过渡统一」这句话不含它——否则将来审计会拿这条问「为何 .15s 还在」。
⑧ 我的页三档：按压缩放挂卡根还是挂wrapper 挂卡根 .acsv-gcell（键不缩） 我的页三档的卡外面套了 .acsv-favcell（cssraw 1446–1447），管理键 absolute 挂在这个 wrapper 上（cssraw 1448）。 压缩放若挂 wrapper，键会跟卡一起缩 且跟着位移——鼠标正瞄准「移动 / 移除收藏」时按钮自己跑掉，是最坏的手感。 挂卡根则键稳住（本稿 ③A 按此画）。代价：按压瞬间封面缩、键不缩，两者边界有 0.015 倍相对位移（250 宽卡上约 3–4px）——肉眼可接受，属克制档。
