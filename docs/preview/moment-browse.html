附：口径与落地风险（待你裁决 / 已在稿中按此画）

1. 两套皮肤 = 同 DOM + 皮肤根类分派（暗色为基底，浅色走 .acsv-mp 覆盖）——沿用广场单源惯例，不另立第二份样式。
2. 【已发现的缺口】 .acsv-mp 未覆盖视频/文章条（scover/sbody/stitle/sdesc/sinfo/tag/mdur），本特性必撞，落地时补齐；稿中右栏已按补齐后的样子画。
3. 【复用禁区】 广场取数的规整函数带 24h 窗口 + 3h 新鲜度回填（squarePageOf），那是广场专用；个人动态是历史流，套上去会把 24 小时前的动态全砍掉 ⇒ profile 流必须另写规整（纯 pcursor 翻页）。
4. 空间页是否要「发现 N 条新动态」轮询：广场有；空间页看的是别人，建议不要（省请求），只在进 tab 时拉一次 + 触底翻页。稿中把发现条画出来了，可删。
5. 「动态」标签要不要计数：feed/profile 不回总数 ⇒ 无计数（原生标签有计数，这里是唯一不一致处）。
6. 我的页数据＝我自己的 profile 流（三合一混排）；若只要图文动态需客户端过滤，分页会别扭，建议照服务端口径。
7. 空间页注入的幂等/自愈：现有 uppage 只有 20 拍轮询、无 MutationObserver，站点 SPA 重渲染会冲掉注入项 ⇒ 新 tab 应照 memberplaza 补 MO 自愈（顺带把「小视频」标签也救回来）。
8. 「我的」页 tab 顺序与默认落地（本稿已改）：「动态」排第 1、且默认选中。代码侧＝面板按钮由 Object.keys(panels).forEach 派生（键序即按钮序，动态键写在最前即可），默认项＝select('<id>') 的入参； 进页即拉一次 profile 流（原本默认落「观看历史」也会拉一次，代价等价，无新增请求量）。
